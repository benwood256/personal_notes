*Variable naming when they have units*

Variables with units (size, time, height, etc...) should include the unit in the variable name (i.e. time_in_seconds, megabyte_size)


*Deep Modules/classes*

Make larger classes that are very easy to understand (i.e. deep modules) compared to many small classes (that are shallow)
   Deep modules can do a lot (large in functionality) but its clear what they do & how they do it, they are easy to understand
   Shallow modules do very little but can still be confusing

For the above, here's an example:
   In an OS you need to open & close a file so you can write in it
   In Unix its 1 command (i.e. echo "hello" > test.txt) -> this hides the complexity by opening & closing the file without you manually doing it
   As someone using a terminal, I already know the file needs to be opened & closed, so hiding this with 1 command is perfectly fine

   However, in Java, you need 3 command/lines to write to a file -> open file, write to it & close the file
   This makes code messier as it's common to write to a file & this doesn't make it any easier to understand than in Unix

I need to develop the skill of looking ahead & work out what classes will be used often (make these deep)
Ones that will be used less often, make them smaller but they should still be easier to understand & use


*Temporal Decomposition*

If, I had a game & when a goal was scored in it, this would trigger the goal class, this gives the user 1 point
The class also then creates a goal animation, resets the ball position & resets the player position -> the order matters

If this was separated into multiple classes, it might get confusing when writing the code what order each of these needs to be called
When writing the code, I'd have to remember each time, what order each of these functions needs to be called in
(for this example its obvious, but with others it would not be as clear)

So, all of these should be called at once, to make it simpler for me

** General (including keywords & terms)

3. Win + up arrow

4. Both are a way of converting human written code into binary, so it can executed
   Compiled    -> translate the human written code into a binary code file
   Interpreted -> the computer has a built in interpreter which translates the human written code line by line

5. UEFI         -> Firmware that initialises hardware & launches EFI applications
   Boot Manager -> Part of UEFI that decides which EFI program to start
   Bootloader   -> Loads the OS kernel (GRUB or Windows Boot Manager)

6. API (Application Programming Interface) is a way for different software systems to communicate with each other

7. TCP (Transmission Control Protocol) is a reliable protocol that ensures data is delivered accurately and in order

8. UDP (User Datagram Protocol) is a faster but less reliable protocol that sends data without checking for errors or order

9. DNS (Domain Name System) translates human-readable domain names (like google.com) into IP addresses

10. FTP (File Transfer Protocol) is used to transfer files between a client and a server over a network

11. SMTP (Simple Mail Transfer Protocol) is used to send emails between servers

12. To take data in 1 format & convert it into a format that a program can understand

* Regex

Regex -> short for regular expression, is a sequence of characters that specifies a search pattern in text
         Its used for searching, validating & manipulating strings based of search patterns

Regex was made for _Unix Systems_ (the idea is older but they first made it popular)

Bash also uses it -> grep (search text), sed (search & replace) & awk (pattern matching) all uses regex
Emacs & Vim have their own flavours (i.e. ~:%s/let/const/g~ -> replace all instances of 'let' with 'const')
Programming languages can also use Regex, you import a library (i.e. import re -> then you can search in a .py file)

Use the websites in 'Personal Projects' to slowly learn it
