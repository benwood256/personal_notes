*Recap Answers*

1. A Promise is an object that represents the eventual completion (success) or failure of an asynchronous operation and its resulting value

2. Pending   –> The operation is still in progress
   Fulfilled –> The operation completed successfully
   Rejected  –> The operation failed

3. const promise = new Promise((resolve, reject) => {
        if (true) {
            resolve("Success");
        } else {
            reject("Error");
        }
   });

4. resolve()  -> marks the Promise as fulfilled and returns a successful result

5. reject()   -> marks the Promise as rejected and returns an error or reason for failure.

6. .then()    -> runs code after a Promise has been fulfilled and receives the resolved value
                 the resolved value is the value a Promise gives you when it successfully finishes

7. .catch()   -> handles errors if a Promise is rejected

8. .finally() -> runs code after a Promise finishes, whether it succeeds or fails

9. Promise chaining links multiple .then() methods together so each step waits for the previous one to finish

10. Promise.all([promise1, promise2, promise3])
        .then(results => {
            console.log(results);
        });

11. Promise.all() immediately rejects, and the remaining results are ignored

12. Promise.all() stops if any Promise rejects
    Promise.allSettled() waits for all Promises to finish, regardless of whether they succeed or fail

13. The async keyword declares a function as asynchronous, allowing the use of await inside it

    async function getData() {
    }

14. An async function always returns a Promise, even if it returns a normal value

        async function example() {
            return 10;
        }

    Returns:

        Promise.resolve(10);

15. await pauses the execution of an async function until a Promise has been fulfilled or rejected

    const response = await fetch(url);

16. await can only be used inside an async function (or at the top level of supported JavaScript modules)

17. Use a try...catch block

        async function getData() {
            try {
                const response = await fetch(url);
            } catch (error) {
                console.log(error);
            }
        }

18. async/await makes asynchronous code look more like synchronous code, making it easier to read
    .then() uses callbacks to handle Promise results

19. await allows code to be written in a top-to-bottom order, reducing nested callbacks
    and making complex asynchronous code easier to understand and debug

*Recap Answers*

1. SQL stands for Structured Query Language. It is used to communicate with and manage relational databases
   SQL can be used to retrieve, insert, update, and delete data, as well as create and modify database structures

2. Query     -> An SQL command that asks the database to do something (i.e. retrieve or manipulate data)
   Sub-query -> A query inside another query

   Example:
   SELECT StudentName
   FROM Students
   WHERE StudentID IN (
       SELECT StudentID
       FROM Enrolments
       WHERE CourseID = 'C001'
   );

   i.e. your asking the database a question -> what are the name of these students?
        then your asking another question   -> which students are enrolled in C001?

3. WHERE filters individual rows before grouping takes place, while HAVING filters groups after GROUP BY has been applied

4. A primary key is a column, or combination of columns, that uniquely identifies each row in a table.
   It must contain unique values and cannot contain NULL values

5. A foreign key is a column that creates a relationship between two tables.
   It usually references the primary key of another table and helps maintain relationships between tables

6. SELECT is used to retrieve data from a database

7. DISTINCT removes duplicate values from the results returned by a query

8. DELETE removes selected rows and can use a WHERE condition. TRUNCATE removes all rows while keeping the table structure
   DROP removes the entire table, including its structure

9. ORDER BY is used to sort query results. ASC sorts in ascending order, while DESC sorts in descending order

10. GROUP BY groups rows with the same values. It is commonly used with aggregate functions such as COUNT(), SUM(), and AVG()

11. Aggregate functions perform calculations on multiple rows. Common examples are COUNT(), SUM(), AVG(), MIN(), and MAX()

12. An INNER JOIN combines two tables and returns only the rows where a matching value exists in both tables

13. A LEFT JOIN returns all rows from the left table, including rows that do not have a match in the right table
    An INNER JOIN only returns rows where a match exists in both tables

    i.e. Customers Table
         | id | name  |
         |  1 | Alice |
         |  2 | Bob   |

         Orders Table
         | id | product |
         |  1 | Laptop  |
         |  3 | Phone   |

         LEFT JOIN Table -> if you only searched the left table you would not get the product information
         | name  | product |
         | Alice | Laptop  |
         | Bob   | NULL    |

14. UNION combines query results and removes duplicates. UNION ALL combines query results but keeps duplicates

15. NULL represents a missing, unknown, or unavailable value. It is not the same as 0, an empty string, or FALSE

16. We use IS NULL because NULL represents an unknown value and cannot be compared using =

    WHERE column_name IS NUL

    To find values that are not NULL

    WHERE column_name IS NOT NUL

17. A subquery is a query inside another query. It is useful when the result of one query is needed by another query

18. IN checks whether a value matches a value in a list or sub-query result
    EXISTS checks whether a subquery returns at least one row

19. An index is a database structure that helps the database find data more quickly
    Indexes can improve search performance but require additional storage and can slow down INSERT, UPDATE, and DELETE operations

20. A Common Table Expression (CTE) is a temporary named result set that can be referenced within a query
    It is created using the WITH keyword and can make complex queries easier to read

21. The logical order of SQL execution is approximately:

    SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

22. SELECT   -> chooses which columns or results to return
    FROM     -> choose the table to get the data from
    WHERE    -> filters individual rows before grouping
    GROUP BY -> groups rows that have the same values
    HAVING   -> filters the groups after they are created
    ORDER BY -> sorts the final results
    LIMIT    -> restricts how many rows are returned

    Example:
        SELECT department, COUNT(*) AS employee_count
        FROM employees
        WHERE salary > 50000
        GROUP BY department
        HAVING COUNT(*) >= 2
        ORDER BY employee_count DESC
        LIMIT 3;

    SELECT department, COUNT(*)  → Choose the department name and employee count to display
    FROM employees               → Start with the employees table
    WHERE salary > 50000         → Keep only employees earning more than £50,000
    GROUP BY department          → Group the remaining employees by department
    HAVING COUNT(*) >= 2         → Keep only departments with at least 2 employees
    ORDER BY employee_count DESC → Sort from highest employee count to lowest
    LIMIT 3                      → Return only the top 3 results

*Recap Answers*

1. The /etc directory contains system-wide configuration files

    Examples include configuration files for services, networking, users, and other system settings

    For example:
        ~/etc/passwd~ -> user account information
        ~/etc/ssh/~   -> ssh server configuration
        ~/etc/fstab~  -> filesystem mount settings

2. The /var directory contains variable data, data that changes (or grows) whilst the system is running

    It commonly contains things such as:
        Log files
        Spool files
        Caches
        Application data

    For example:
        ~/var/log/~   -> system logs (i.e. ~/var/log/journal/~ -> systemd journal entries for persistent logs;
                                         ~/run/log/journal/~ -> volatile logs, ones lost after reboot are stores in 
        ~/var/cache/~ -> application caches
        ~/var/lib/~   -> persistent application data

3. The /tmp directory is used to store temporary files

    Programs can use /tmp when they need somewhere to temporarily store data. Files in /tmp may be removed automatically
    when the system is restarted or according to system cleanup policies

4. The /usr directory contains many user-space programs, libraries, documentation, and other read-only/shareable data

    Common directories include:
        ~/usr/bin/~   -> contains many user commands
        ~/usr/lib/~   -> contains libraries
        ~/usr/share/~ -> contains architecture independent data & documentation

    On modern Linux systems, /usr often contains much of the software that used to be placed directly in /bin or /sbin

5. Traditionally, /bin contains essential executable programs required for basic system operation (i.e. terminal command files)

    Examples of commands historically found there include:
        ls
        cp
        mv
        cat

    On many modern Linux distributions, /bin is a symbolic link to /usr/bin (including mine)

6. The /sbin directory traditionally contains system-administration executables, many of which are intended for system management

       Examples include: tools for managing filesystems, networking & system startup

   On many modern Linux distributions, /sbin is a symbolic link to /usr/sbin (including mine)

7. The /dev directory contains device files that represent hardware and virtual devices as well as special files to manipulate data

   Examples:
       ~/dev/sda~    -> represents a storage device
       ~/dev/null~   -> discards data written to it
       ~/dev/random~ -> provides random data

8. The /proc directory is a virtual filesystem created by the kernel that provides information about running processes and the Linux kernel
   

   Examples:
       ~/proc/cpuinfo~ -> provides CPU information
       ~/proc/meminfo~ -> provides memory information
       ~/proc/[PID]/~  -> when an process starts, the kernel creates a process & gives it a PID, then it creates a directory containing
                        many virtual files about that specific process
                        These are per session information, so are cleared when you exit the process

9. The /sys directory is another virtual filesystem that provides information about hardware, devices, drivers, and the Linux kernel

   It allows the kernel to present devices & their attributes in an organized structure
   System tools can read from & sometimes write to files /sys to view or modify device & kernel settings

10. The /boot directory contains files required to boot the Linux operating system
    This includes the Linux kernel, initramfs, and systemd-boot

11. The /run directory contains temporary runtime data created since the system booted
    This can include process IDs, sockets, and other information used by running services

    Its usually stored in memory & is cleared when the system shuts down or reboots

12. The /lib directory traditionally contains essential shared libraries and kernel modules required by programs and the operating system
    On many modern Linux systems, /lib is a symbolic link into /usr/lib (including mine)

13. An absolute path starts from the root directory / and gives the complete path of a file or directory.

     Example:
     ~/home/alex/documents/file.txt~

     A relative path starts from your current directory

     Example:
     ~cd documents~ -> uses a relative path as it knows to include the path your currently in & add /documents

14. A hard link is another directory entry that refers to the same underlying file data

     A symbolic link, or symlink, is a special file that points to another file or directory

     You can create a symbolic link using:

     ~ln -s original.txt shortcut.txt~

     If the original file is removed, a symbolic link can become a broken link because it points to something that no longer exists

15. ls -ld /bin
    lrwxrwxrwx 1 root root 7 ... /bin -> usr/bin
    This shows /bin is a symbolic link to usr/bin

*Recap Answers*

1. A linked list is a sequence of nodes where each node stores a value and a pointer/reference to another node
   Access is O(n), while insertion/deletion can be O(1) when you already have the relevant node

2. A stack is a LIFO (Last In, First Out) data structure. You add with push and remove with pop, both usually O(1)
   It is commonly used for parentheses, DFS, and monotonic-stack problems

3. A queue is a FIFO (First In, First Out) data structure
   Elements are added to the back and removed from the front. It is fundamental to BFS

4. A deque (double-ended queue) allows insertion and deletion from both ends, usually in O(1)
   It is useful for sliding-window and monotonic-queue problems

5. A heap is a tree-based structure that efficiently gives access to the minimum or maximum element
   A min-heap gives the smallest element first; a max-heap gives the largest

    Peek: O(1)
    Insert: O(log n)
    Remove: O(log n)

6. A binary tree is a tree where each node has at most two children, usually called left and right
   Important operations include DFS, BFS, and tree traversals

7. A BST is a binary tree where values in the left subtree are smaller and values in the right subtree are larger than the current node
   A balanced BST supports search, insertion, and deletion in O(log n)

8. A trie is a tree-like data structure designed for storing strings by their prefixes
   It is useful for prefix searches, autocomplete, dictionaries, and word problems

9. A graph consists of vertices/nodes connected by edges. Graphs can be directed or undirected and weighted or unweighted
   They are commonly represented using an adjacency list or adjacency matrix

10. Union-Find (DSU) maintains groups of connected elements
    Its two main operations are find (identify a group's representative) and union (merge groups)
    With path compression and union by rank/size, operations are effectively O(1) amortized

        Ensures data arrives correctly
        Checks for errors
        Resends missing data
        Keeps packets in the correct order

    Examples of TCP usage:
        Web browsing
        Email
        File transfers

    TCP focuses on accuracy and reliability rather than speed

3. UDP (User Datagram Protocol) is a networking protocol that sends data quickly without guaranteeing delivery

    UDP:
        Does not check whether packets arrive
        Does not resend lost packets
        Has less overhead than TCP
        Is faster but less reliable

        Online gaming.

        Upload files to a server
        Download files from a server

    SMTP is responsible for transferring outgoing emails from the sender's mail server to the recipient's mail server

    Example:

15. match() finds text that matches a Regex pattern and returns the matches

        Example:
        "abc123".match(/\d+/);

        Returns:
        123

    search() finds the position of the first match.

        Example:
        "hello123".search(/\d/);

        Returns:
        5

    replace() finds matching text and replaces it.

        Example:
        "hello123".replace(/\d+/,"456");

        hello456

    match → find and return matches

    replace → find and substitute text
