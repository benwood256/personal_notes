1. A Promise is an object that represents the eventual completion (success) or failure of an asynchronous operation and its resulting value

   Fulfilled – The operation completed successfully
   Rejected – The operation failed

3. const promise = new Promise((resolve, reject) => {
        if (true) {
            resolve("Success");
        } else {
            reject("Error");
        }
   });

4. resolve() marks the Promise as fulfilled and returns a successful result

5. reject() marks the Promise as rejected and returns an error or reason for failure.

6. .then() runs code after a Promise has been fulfilled and receives the resolved value

7. .catch() handles errors if a Promise is rejected

8. .finally() runs code after a Promise finishes, whether it succeeds or fails

9. Promise chaining links multiple .then() methods together so each step waits for the previous one to finish

10. Promise.all([promise1, promise2, promise3])
        .then(results => {
            console.log(results);
        });

11. Promise.all() immediately rejects, and the remaining results are ignored

12. Promise.all() stops if any Promise rejects
    Promise.allSettled() waits for all Promises to finish, regardless of whether they succeed or fail

13. The async keyword declares a function as asynchronous, allowing the use of await inside it

    async function getData() {
    }

14. An async function always returns a Promise, even if it returns a normal value

        async function example() {
            return 10;
        }

    Returns:

        Promise.resolve(10);

15. await pauses the execution of an async function until a Promise has been fulfilled or rejected

    const response = await fetch(url);

16. await can only be used inside an async function (or at the top level of supported JavaScript modules)

17. Use a try...catch block

        async function getData() {
            try {
                const response = await fetch(url);

                console.log(error);
            }
        }

18. async/await makes asynchronous code look more like synchronous code, making it easier to read
    .then() uses callbacks to handle Promise results

19. await allows code to be written in a top-to-bottom order, reducing nested callbacks

 *Recap Answers*

1. A network protocol is a set of rules that define how data is transmitted and received between devices on a network

2. TCP (Transmission Control Protocol) is a reliable protocol that ensures data is delivered accurately and in order

3. UDP (User Datagram Protocol) is a faster but less reliable protocol that sends data without checking for errors or order

4. DNS (Domain Name System) translates website names (a url) into IP addresses

5. FTP (File Transfer Protocol) is used to transfer files between a client and a server over a network

6. SMTP (Simple Mail Transfer Protocol) is used to send emails between servers

7. Protocol → rules for communication (e.g. HTTP, TCP)
   Port → a numbered endpoint used to direct traffic (e.g. port 80 for HTTP)

8. A client (your browser) wants to load a website
   The browser asks DNS to translate the domain name (i.e. ~https://google.com~) into an IP address
   DNS returns the server's IP address
   Your browser connects to the server (hosting place of the website)
   The server sends the website data back to your browser (DNS isn't needed as the server uses your IP address)

9. Server gives you a public key (they send it with the certificate it's a padlock anyone can close but only the server can open)
   The browser generates a random secret key
   You encrypt this secret key using the server's public key (meaning the server is the only one that can decrypt it)
   So when the data is sent over, it's encrypted with the public key
   The server receives this & decrypts it's own encryption with the public key to receive the secret key
   Then they can decrypt the data using the secret key

10. There's a Request HTTP message when a client requests data from a server
    & a Response HTTP message when the server sends its reply

11. The method -> GET, POST, DELETE, etc...
    The path   -> the location of the data (i.e. /index.html)
    The HTTP Version

12. The HTTP version
    The status code
    The status message

13. 100s -> the request is continuing
    200s -> success codes
    300s -> redirection codes
    400s -> client error codes (there was a problem)
    500s -> server error codes (the request was accepted but there was an error on the server side)

14. GET    -> retrieve data from a server
    POST   -> send data to input into the server
    DELETE -> remove a resource
    PUT    -> update or replace an existing source
    PATCH  -> partially update a resource
